# RC3 — Integrated Renewal and Financial Stewardship (engineering preview)

Based on the approved two-channel intake direction: online and staff-assisted walk-ins; registry administrators approve documents, COWL finance authorizes payment obligations; verified full settlement plus approval validates each eligible assignment. No payment alone changes a registration.

RC3 is isolated on its own Git branch and preview environment. Its private TEST rehearsal schema is separate from RC2 finance ledgers and from member_ministries. Registry administrator authorization uses the existing active administrator allowlist; finance authorization uses the existing active COWL finance verifier grant. No new account grants were made. No real parish account is available in TEST, so online intake is currently a staff-operated rehearsal, not a public upload or registration endpoint. Walk-in intake uses the same application records. The sample PHP 50 rate is illustrative; full exact OTC payment is the only enabled RC3 settlement path at this stage. The simulated payment and synthetic renewal update commit in the same database transaction; dates use Asia/Manila and a one-calendar-year interval. Duplicate assignment/year, unauthorized transitions, incorrect amounts and duplicate payment are rejected. RC2 receipt and remittance features remain accessible separately; RC3 does not yet post to their ledger. Existing design assets and sign-in shell are unchanged.

Remaining before integration: scoped parish contact identities and real private document intake; approved fee schedule and exemptions; per-assignment roster matching against TEST registry; reviewed linking of authorized obligations to existing FS payment, receipt, remittance and allocation RPCs; automatic validation adapter with idempotency and documented reversal behavior; real certificate eligibility; end-to-end authenticated QA, accessibility, and independent production migration/approval. Never apply this synthetic rehearsal migration to production.
