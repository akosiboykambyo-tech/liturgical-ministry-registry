# RC3.1 unified intake correction
Staff intake now always submits walk_in. Online applicants use the connected /demo/finance/parish rehearsal, which uses the same existing TEST applications, memberships and audit records. An actual authorized Registry TEST session is required as the rehearsal operator. The sample SMS challenge is UI-only, not authorization. No real parish account, credentials, personal data, document bytes, or OTP delivery. The standalone policy mock remains browser-local and explicitly labels that fact; it links to the connected rehearsal. Registry review queue loads both channels on entry or refresh and supports source/status/search filtering. Returning an online application blocks approval until the parish rehearsal resubmits a corrected generated letter on the same reference; roster changes are not implemented. A document receipt date and 12-month illustrative retention date are recorded, without file storage or deletion. The chosen payment preference is informational and does not bypass existing finance authorization. Existing sample records preserved. Migration is TEST-only, no production or encryption modification.
Acceptance: authenticate with the existing Registry TEST account, open Parish submission rehearsal, select sample parish and mock SMS code, select unused assignments and generated letter, submit. Open Review Queue; filter Online; return with a reason; open same parish and My Applications, resubmit correction; review and approve; finance authorizes full payment as before. Refresh queue to see new submissions. No automatic background polling.
